# Preludio 项目规格

更新日期：2026-10-24。本文是项目级工作规格；描述目标行为与验收条件，不表示相关 API 已经实现。

## 1. 产品定位

**Preludio — On-device radar nowcasting.**

**Forecast the rain before it begins. On your device.**

Preludio 面向消费设备上的雷达短临外推：接收一段雷达观测序列，在用户自己的设备上执行模型，返回带有时间、空间和模型来源信息的预测场。首个消费者是 [Radiust](https://github.com/chorust/radiust)，首批目标环境是 macOS 桌面和网页。

项目以可复用的推理组件为工作方向。浏览器扩展、iPhone、Android 和手表属于后续探索；当前不承诺同一模型、同一执行引擎或同一性能覆盖所有设备。

## 3. 使用场景与范围

首个完整场景是：Radiust 提供同一网格上的连续观测及其元数据，Preludio 校验并转换为模型输入，在本地完成推理，再将预测场及其有效时间交回 Radiust 展示。展示必须能够区分历史观测与模型预测。

在此之前，开发者应能用固定样本重现“观测文件 → 预处理 → 本地推理 → 参考结果比较”的完整链路，以判断模型是否适合继续部署。

首个运行时里程碑包括单模型加载、明确的数据契约、本地推理、预测元数据、错误报告和目标设备测量。模型训练与选择留在 Onix；数据来源接入、科学解码和地图交互由消费者负责。云端推理服务、完整天气 App、多模型市场、降雨到达提醒和所有移动平台 SDK 不在首版范围内。

“本地推理”允许联网获取观测与模型文件。模型和输入准备好以后，计算链路应能断网运行；不自动把推理请求转发给云端。

## 4. 数据契约

### 4.1 所有模型都必须说明的语义

| 对象 | 必须明确的信息 |
| --- | --- |
| 观测序列 | 帧标识、来源、有效时间与严格时间顺序、编码、数值、质量与缺测含义；相邻时间间隔规则按模型合同定义 |
| 空间网格 | 输入数组轴方向与像元定位约定；坐标参考和地理参照是否必需由模型契约定义 |
| 模型输入 | dtype、shape、轴顺序、值域、预处理顺序，以及时间和尺寸兼容条件 |
| 模型输出 | dtype、shape、轴顺序、编码或单位、运行时预测时效、输出网格和有效区域 |
| 预测来源 | 输入帧标识、最后观测时间、模型与产物标识、生成时间、实际执行后端 |

公共契约字段及语言绑定见首个运行时的 [API 合约](../specs/001-local-nowcast-runtime/contracts/)。当前 Ghost 的运行时契约规定接受四帧、单通道 raw u8 灰度输入，四帧具有相同的任意正 `[H,W]`；输入 resize 到模型 tensor 空间尺寸。manifest 中的 observation grid id/shape 和 cadence 是训练/reference 元数据，不限制运行时接受。

当前模型的输入灰度含义须符合 duckomo 灰度约定。输入地理参照不是必需项；本运行时不执行 dBZ 等物理转换，输出保持 `georeferenced = false` 且没有 CRS/affine。缺测、不在覆盖区和有效无回波仍可区分：当前策略拒绝 Missing/OutsideCoverage；有效无回波是 `Valid` 且 raw u8 为 0。

观测必须恰有四帧且有效时间严格递增，不要求等间隔。可选序列级 `zero_threshold: Option<u8>` 只把严格小于阈值的值在 `/255` 和 resize 前置零；缺省时不置零，0 无效果。

预测有效时间由最后一帧观测时间加每个输出 lead 计算，不能用推理完成时间替代。以输入首末时间差除以 3 得到平均间隔秒数，对每个输出索引 k（从 1 开始）分别将 `k × 平均间隔` 按最近秒、半秒向上取整；输出数量取 `tensor_output.shape[1]`。`lead_minutes` 为整秒 lead 除以 60 的浮点数。生成时间单独保留。

### 4.2 初始 GhostUNet3D 模型

| 项目 | 已确认内容 |
| --- | --- |
| checkpoint | Onix `ghost_unet3d_wmse/2026-10-23_23-54-23` 的 `step_22000.ckpt` |
| 输入 tensor | float32 `[1, 4, 448, 448]`，轴为 batch / time / y / x，时间从旧到新 |
| 原始帧 | 四帧单通道 u8；每帧尺寸任意但为正且四帧相同。已记录固定样本为 732×732，属于该参考窗口，不是输入限制 |
| 记录窗口时间 | 该 reference 的帧间隔为 6 分钟、首末相差 18 分钟；运行时只要求严格递增 |
| 预处理 | 可选阈值置零（严格 `< threshold`）→ u8 / 255 → 抗锯齿双线性缩放至模型 tensor 448²，`align_corners=false` → float16 → float32；无旋转 |
| 输出 | float32 `[1, 20, 448, 448]`，轴为 batch / lead_time / y / x，值域 `[0, 1]` |
| 训练配置时效 | 固定参考配置列出 +6、+12、…、+120 分钟；运行时时效由输出帧数与输入平均间隔计算 |
| 语义边界 | 输入灰度须符合 duckomo 灰度约定；本仓库没有证据证明 Duckomo 原始灰度转换实现。物理 dBZ 映射与地理网格信息未知，但不属于当前 raw-u8 接受条件 |

该模型只按 duckomo-compatible raw u8 灰度解释输入；不得直接输入 dBZ 浮点场，也不得将输出标为 dBZ、雨强或降雨概率。当前运行时不提供物理量转换或地理空间还原，输出网格保持 `georeferenced = false`。

20 帧与固定 reference 中每 6 分钟一帧是模型/样本元数据，不是时间间隔接受限制或准确性结论。运行时 lead 时间按输出帧数和输入平均间隔计算；早期讨论中的示例不构成本模型契约。

## 5. 功能要求

以下是后续运行时要求；现有导出脚本仅实现其中的部署验证子集。

| 编号 | 要求 | 验收依据 |
| --- | --- | --- |
| FR-01 | 加载带输入输出说明和内容哈希的模型产物；拒绝不兼容的契约或损坏产物 | 正常样本可加载，哈希不符和不支持的契约明确失败 |
| FR-02 | 推理前校验四帧、严格递增时间、正且相同的输入尺寸、raw u8 编码和质量信息 | 有效不等间隔序列通过；缺帧、乱序/重复、非正或不一致尺寸、错误编码、Missing/OutsideCoverage 被拒绝；manifest cadence/grid id/shape 不作为拒绝条件 |
| FR-03 | 按契约执行 u8 预处理和输出校验，不执行物理量或地理空间还原 | 可选 threshold 在 `/255` 与 resize 前严格 `< t` 置零；目标空间尺寸来自模型 tensor shape |
| FR-04 | 在用户设备执行推理，检查输出 shape、有限值和声明的编码范围 | 已准备模型和样本时断网完成预测；失败时返回明确原因 |
| FR-05 | 返回预测有效时间、非地理参照输出网格、编码、输入来源、模型身份与实际后端 | lead count 来自 `tensor_output.shape[1]`，有效时间按平均输入间隔分别四舍五入至整秒 |
| FR-06 | 支持 Radiust 通过适配层传入符合 duckomo-compatible raw u8 的观测并消费预测 | 真实来源完成适配和时间轴展示；不得宣称物理量预测或地理对齐 |
| FR-07 | 每个声明支持的模型 / 后端组合都有参考样本与验证记录 | 未验证组合不列入支持范围；后端切换可见且不切换到云端 |

## 6. 质量与发布条件

| 编号 | 要求 |
| --- | --- |
| NFR-01 数值一致性 | 当前 float32 ONNX 基线使用 `rtol=1e-4, atol=1e-5` 逐元素比较 PyTorch 参考，并报告最大及平均绝对误差。精度或模型改变后重新验证 |
| NFR-02 性能可复核 | 在明确设备、系统、引擎版本、线程与后端下记录加载、冷启动、热推理、多次运行分布及峰值内存；目标预算在基准测试前确定 |
| NFR-03 可追溯 | 权重、配置、导出代码与预处理变化都有版本或哈希，以及对应的样本和结果记录 |
| NFR-04 可集成 | 消费者无需依赖训练环境；长时间推理不阻塞应用交互；错误可由调用方处理 |
| NFR-05 能力边界 | 支持范围细化到模型、设备与后端；后端存在或文件导出成功不等于组合可用 |

首批预算（2026-10-24 确认）：目标设备上单次热推理 ≤ 8 秒，内存以 WASM 实测约 1.7 GiB 进程常驻为可接受量级；下载体积与最低设备要求尚未确定。Linux 原生单次约 4.10 秒、WASM 在 Apple M4 Pro 上 1 线程约 7.6 秒 / 4 线程约 2.2 秒，均为实验记录，正式验收以目标 macOS 与浏览器实测为准。

部署正确性与气象效果分别验收。面向真实用户发布前，需建立包含不同回波强度、天气过程与预测时效的独立评估集，预先约定指标与基线，并报告逐时效结果；目前没有可承诺的准确率或可用预报时长。

## 7. 关键验收场景

1. **固定样本重放**：给定已记录的模型、配置和四帧观测，重现模型输入，并通过 CPU 数值对齐检查。现有 spike 已完成一个窗口。
2. **不兼容输入**：缺一帧、打乱/重复时间、尺寸非正或帧尺寸不一致、使用不匹配编码或含 Missing/OutsideCoverage 时，在推理前得到可解释错误；严格递增的不等间隔时间通过检查。
3. **预测可追溯**：最后观测为 `2023-11-30T09:42:00Z` 时，固定参考输入的第一帧有效时间为 `09:48:00Z`、最后一帧为 `11:42:00Z`；其他输入按平均间隔计算，另行记录实际生成时间。
4. **本地与交互**：模型和数据已在设备上，断网仍可预测；消费者能够展示运行状态，并明确区分观测与预测。
5. **支持声明**：只有通过参考比较与设备测量的组合才能进入支持列表；执行失败时暴露实际原因。
