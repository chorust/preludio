# Feature Specification: 端侧雷达短临预测运行时（首个运行时里程碑）

**Feature Branch**: `001-local-nowcast-runtime`

**Created**: 2026-10-24

**Status**: Draft

**Input**: User description: "docs/spec.md, 完成相关spec设计"

本规格把 [项目规格](../../docs/spec.md) 中的“首个运行时里程碑”和首个完整场景整理为一个可规划的功能：在用户设备上加载单个模型、校验观测序列、执行本地推理，并返回带有效时间与来源信息的预测，最终交给 Radiust 展示。项目级定位、模型契约细节和数值证据分别以 [docs/spec.md](../../docs/spec.md)、[docs/ghost-unet3d.md](../../docs/ghost-unet3d.md) 为准。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 固定样本本地重放 (Priority: P1)

开发者拿到一个已记录的模型产物、它的配置和一组四帧观测样本，在自己的设备上不依赖训练环境运行完整链路：加载模型 → 生成模型输入 → 本地推理 → 与参考结果比较。结果告诉开发者该模型在这台设备上的部署是否正确，以决定是否继续推进。

**Why this priority**: 后续所有接入和展示都依赖“本地推理结果与参考一致”这一前提；没有它，任何预测都无法被信任。项目已有一组 Linux CPU 参考样本，可直接作为验收依据。

**Independent Test**: 分别在目标 macOS 设备的原生应用和目标浏览器的网页中，用已记录的 step 22000 模型与 AZ9002 四帧样本运行一次，比较输出与参考结果，并确认全过程无需训练环境、断网可完成。

**Acceptance Scenarios**:

1. **Given** 已准备好的模型产物、内容哈希与四帧固定观测，**When** 开发者在 macOS 原生或浏览器中运行重放，**Then** 生成的模型输入与已记录输入逐元素一致，预测与参考输出在 `rtol=1e-4, atol=1e-5` 内逐元素一致，并报告最大及平均绝对误差。
2. **Given** 模型产物与样本已在设备本地，**When** 设备断开网络后运行重放，**Then** 预测正常完成，过程中没有任何推理请求离开设备。
3. **Given** 模型文件内容与声明哈希不符，**When** 开发者尝试加载，**Then** 加载被拒绝并报告哈希不符，不产生任何预测。

---

### User Story 2 - 不兼容输入在推理前被拒绝 (Priority: P2)

调用方提交固定四帧、严格按时间递增的观测。对当前 Ghost 模型，每帧必须是同尺寸的正高宽单通道原始 u8 灰度，值域 `[0,255]`，灰度含义须符合 duckomo 灰度约定；不要求相邻时刻等间隔，也不按 manifest cadence、grid id 或 grid shape 拒绝。错误帧数、乱序、非正或不一致尺寸、编码不符及 Missing/OutsideCoverage 质量标记在推理前被拒绝。

**Why this priority**: 错误输入产生的“看似正常”的预测会把错误天气状态展示给用户；这是数据正确性的底线，必须在接入真实来源前建立。

**Independent Test**: 提交四帧有效样本、缺一帧、乱序时间、不等间隔时间、非正或不一致尺寸、错误编码以及带 Missing/OutsideCoverage 质量标记的序列。只有违反输入契约的样本在推理前失败；不等间隔的严格递增时间应通过。

**Acceptance Scenarios**:

1. **Given** 四帧单通道 u8 输入尺寸相同且均为正、编码匹配、时间严格递增（间隔可以不同），**When** 提交预测，**Then** 校验通过并将输入 resize 到模型 tensor 的空间尺寸。
2. **Given** 只有三帧观测，**When** 提交预测，**Then** 推理前失败并报告实际帧数。
3. **Given** 帧时间重复或乱序，**When** 提交预测，**Then** 推理前以时间未严格递增失败；任意严格递增的不等间隔序列通过时间检查。
4. **Given** 输入高度或宽度非正、四帧尺寸不一致，或使用不匹配编码（例如直接提交 dBZ 浮点场），**When** 提交预测，**Then** 推理前失败；不比较 manifest observation grid id/shape，也不要求 georeference。
5. **Given** 输入含 `Missing` 或 `OutsideCoverage` 质量标记，**When** 提交预测，**Then** 推理前失败；有效无回波以 `Valid` 和 u8 值 0 表示。若设置 `zero_threshold = t`，严格小于 t 的像素在 `/255` 和 resize 前置零；省略时不置零，t=0 无效果。

---

### User Story 3 - 预测可追溯 (Priority: P3)

消费者拿到一份预测后，能从中读出每一帧的有效时间、输出编码与网格、所用输入帧标识、最后观测时间、精确的模型产物身份、生成时间以及实际执行路径，从而判断“这是哪个模型、基于哪些观测、对应哪个天气时刻”的预测。

**Why this priority**: 有效时间和来源信息决定展示是否正确；若用推理完成时间代替有效时间，旧观测会被显示成新的天气状态。

**Independent Test**: 以最后观测时间为 `2023-11-30T09:42:00Z` 的样本运行一次预测，检查结果携带的时间与来源信息。

**Acceptance Scenarios**:

1. **Given** 最后观测时间为 `2023-11-30T09:42:00Z` 的四帧样本，**When** 预测完成，**Then** 结果包含 20 帧预测，第一帧有效时间为 `09:48:00Z`，最后一帧为 `11:42:00Z`，与推理实际运行的时刻无关。
2. **Given** 任意一次成功预测，**When** 读取结果，**Then** 生成时间单独记录且与有效时间不同字段；结果包含输入帧标识、模型身份与内容哈希、实际执行路径，并明确标记为“预测”。
3. **Given** 当前输出仍是训练灰度归一化值且未提供地理参照，**When** 读取结果，**Then** 编码不标为 dBZ、雨强或降雨概率，输出网格 `georeferenced = false` 且没有 CRS/affine。

---

### User Story 4 - 目标设备测量与支持声明 (Priority: P4)

维护者在明确的设备、系统、执行路径和线程配置下测量加载、冷启动、热推理、多次运行分布与峰值内存，并只把通过参考比较和设备测量的“模型 / 设备 / 执行路径”组合列入支持范围。执行失败或切换执行路径时，调用方能看到实际路径与失败原因。

**Why this priority**: 能否交付给用户取决于目标设备上的实测；但它依赖 P1 的正确性基础，因此排在其后。

**Independent Test**: 在选定的 macOS 设备和目标浏览器上按首批预算运行测量，生成测量记录；用一个未验证组合尝试运行，检查它不出现在支持列表且失败原因可见。

**Acceptance Scenarios**:

1. **Given** 首批预算为单次热推理 ≤ 8 秒、内存不超过约 1.7 GiB 的已接受量级，**When** 维护者在 macOS 原生与浏览器中分别完成测量，**Then** 记录包含设备、系统或浏览器版本、执行路径、线程、冷启动、热推理分布与峰值内存，并标明是否满足预算。
2. **Given** 页面未启用多线程所需的隔离条件，**When** 在浏览器中运行预测，**Then** 记录实际线程数，单线程结果同样按首批预算判定，而不是假定多线程性能。
3. **Given** 一个未通过参考比较或设备测量的组合，**When** 查询支持范围，**Then** 该组合不在列表中；请求它时明确失败而非静默切换。
4. **Given** 首选执行路径不可用，**When** 运行时改用另一条已验证的本地路径，**Then** 结果和状态中可见实际路径；任何情况下都不转发到云端。

---

### User Story 5 - Radiust 首次完整接入 (Priority: P5)

Radiust 用户通过适配层提交符合 raw u8 灰度输入契约的四帧观测，并查看本机生成的预测时间、值、模型身份与运行状态。界面清楚区分历史观测和预测；当前输出没有地理参照，不承诺地图位置对齐。

**Why this priority**: 这是项目首个消费者工作流，依赖 Radiust 侧能够提供 duckomo-compatible raw u8 灰度和适配层联调，以及 P1–P4 的运行时能力；物理量换算和地理参照不属于运行时输入要求。

**Independent Test**: 选取一个能够提供符合契约的具体来源，在 Radiust 中提交四帧观测，检查预测时间、模型身份、观测/预测区分和运行/失败状态；不把该结果解释为地理对齐或物理量预测。

**Acceptance Scenarios**:

1. **Given** 一个来源提供 duckomo-compatible raw u8 灰度且四帧尺寸相同、时间严格递增，**When** Radiust 通过适配层提交序列，**Then** 本地预测在时间轴上显示，输出仍标记为非地理参照。
2. **Given** 预测正在运行，**When** 用户继续操作 Radiust，**Then** 界面保持可交互并显示运行状态。
3. **Given** 输入被拒绝或推理失败，**When** Radiust 收到结果，**Then** 显示可理解的失败状态，不显示伪造或过期的预测。
4. **Given** 新观测到达前的旧预测，**When** 用户查看时间轴，**Then** 旧预测保留其原有效时间和生成时间，不被标记为新预测。

---

### Edge Cases

- 模型产物存在但契约版本不受支持，或声明的执行路径未经验证：加载阶段失败并说明原因。
- 当前 Ghost 输入为 u8，不存在 NaN/无穷值；输入尺寸必须为正且四帧相同。有效时间不严格递增时拒绝，不等间隔本身不是错误。
- 帧时间戳重复或时区不一致：视为错时，推理前拒绝。
- 推理输出 shape 不符、含非有限值或超出声明编码范围：视为输出无效，返回错误而不是预测。
- 推理过程中设备资源不足或执行中断：返回执行失败及上下文，不返回部分结果冒充完整预测。
- 观测序列整体陈旧（最后观测距当前很久）：仍按最后观测时间计算有效时间，生成时间单独显示，由消费者决定是否展示。
- 首次使用时模型尚未下载、网络不可用：报告模型不可用，不转向云端推理。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 加载携带输入输出说明与内容哈希的模型产物，并拒绝哈希不符、损坏或契约版本不受支持的产物（对应项目规格 FR-01）。
- **FR-002**: 系统 MUST 在推理前校验恰有四帧、时间严格递增、每帧具有相同的正尺寸、raw u8 编码和 quality 长度；MUST NOT 将 cadence 或 manifest observation grid id/shape 作为拒绝条件。
- **FR-003**: 系统 MUST 区分有效无回波、Missing 与 OutsideCoverage；当前 missing policy 下 MUST 拒绝 Missing/OutsideCoverage，不得自动补帧、补零、插值或执行物理量转换。严格递增但间隔不等的时间必须通过时间校验。
- **FR-004**: 系统 MUST 对当前模型接受单通道原始 u8 `[0,255]` 输入，灰度含义符合 duckomo 灰度约定；可选 sequence-level `zero_threshold: Option<u8>` 仅将严格小于阈值的像素在归一化和 resize 前置零。None 不改变像素，0 无效果。随后 MUST 按模型预处理执行 `/255`、抗锯齿双线性缩放至模型输入 tensor 的空间尺寸及所声明舍入步骤。
- **FR-005**: 系统 MUST 在用户设备上完成推理；模型与观测已在本地时，推理链路 MUST 能在断网状态下完成，且 MUST NOT 将推理请求转发到云端（FR-04）。
- **FR-006**: 系统 MUST 校验推理输出的 shape、有限值与声明编码范围，不满足时返回输出无效错误。
- **FR-007**: 每次成功预测 MUST 返回预测值及编码、非地理参照输出网格、有效时间、独立生成时间、输入帧标识、最后观测时间、模型身份与内容哈希、实际执行路径，并标记为预测。输出帧数取 `tensor_output.shape[1]`；第 k 个时效（k 从 1 开始）为输入平均间隔 `(last-first)/(N-1)` 秒乘以 k 后独立按最近秒、半秒向上取整；`valid_times` 加在最后观测时间上，`lead_minutes` 为这些整秒数除以 60，可为小数。
- **FR-008**: 当前输入只接受 duckomo-compatible raw u8 灰度，不定义从物理量（如 dBZ）的转换；系统 MUST NOT 将输出标为 dBZ、雨强或降雨概率，也 MUST NOT 推断地理位置。输出 MUST 保持 `georeferenced = false` 且不提供 CRS/affine。
- **FR-009**: 失败 MUST 区分为四类：模型或执行路径不可用、输入不兼容、执行失败、输出无效；每类携带足以由调用方处理和诊断的上下文。
- **FR-010**: 系统 MUST 只对通过参考比较和目标设备测量的“模型 / 设备 / 执行路径”组合声明支持；执行路径切换 MUST 对调用方可见（FR-07）。
- **FR-011**: 开发者 MUST 能用固定样本重放“观测 → 预处理 → 本地推理 → 参考比较”全链路，并得到逐元素误差报告。
- **FR-012**: 长时间推理 MUST NOT 阻塞消费者应用的交互，消费者 MUST 能获知运行中、成功、失败状态。
- **FR-013**: 系统 MUST 提供面向 Radiust 的适配，使其能传入观测序列与元数据并消费预测；Preludio 的公共契约 MUST NOT 直接依赖 Radiust 内部数据类型（FR-06）。
- **FR-014**: 权重、配置、导出方式或预处理任何变化 MUST 伴随新的版本或哈希，以及对应的参考样本与验证记录；旧验证结论不得沿用到新产物。

### Key Entities

- **观测序列**：恰好四个从旧到新、时间严格递增的单通道 u8 帧；四帧具有相同的正 `[h,w]`，可选序列级零阈值和质量信息；不要求固定 cadence 或输入地理参照。
- **模型包**：一个可部署模型的完整说明——模型身份与内容哈希、契约版本、输入输出的类型/形状/轴顺序/值域、预处理规则、输出编码与时效、时间与网格兼容条件、已验证的执行路径及参考样本。
- **预测结果**：多帧预测值及编码、输出网格与有效区域、每帧有效时间、生成时间、输入帧标识、最后观测时间、模型身份、实际执行路径；明确标为预测。
- **参考样本与验证记录**：固定输入、参考输出、本地输出、误差统计、运行环境与产物哈希，用于证明某个组合可用。
- **设备测量记录**：设备、系统或浏览器版本、执行路径、线程配置下的加载、冷启动、热推理分布与峰值内存，以及与首批预算的比较结论。
- **支持声明**：通过验证的“模型 / 设备 / 执行路径”组合列表。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在目标 macOS 设备的原生路径和目标浏览器中，固定样本重放的预测与参考输出 100% 元素满足 `rtol=1e-4, atol=1e-5`，并报告最大与平均绝对误差。
- **SC-002**: 契约验证样本集中，满足四帧、raw u8、正且同形尺寸、严格递增时间的有效序列（包括不等间隔）100% 通过；缺帧、乱序/重复时间、非正或不一致尺寸、错误编码及 Missing/OutsideCoverage 100% 在推理前被拒绝，并指明具体出错项。
- **SC-003**: 模型与观测已在本地时，断网状态下 10 次连续预测全部成功，期间设备无任何推理相关网络请求。
- **SC-004**: 输出帧数等于 `tensor_output.shape[1]`；每个时效以四帧首末时间差除以 3 得到平均间隔，分别将 `k × 平均间隔` 按最近秒、半秒向上取整。固定样本 09:24、09:30、09:36、09:42Z 的 20 帧仍为 09:48Z 至 11:42Z；不等间隔样本也须按该规则计算，且结果不依赖运行时刻。
- **SC-005**: 任一份预测结果都能在 1 分钟内由人工追溯到其输入窗口与精确模型产物（通过结果自带的信息，无需外部日志）。
- **SC-006**: 支持列表中的每个组合都有对应的参考比较与设备测量记录；macOS 原生与至少一个目标浏览器各有一个组合进入支持列表，单次热推理 ≤ 8 秒，峰值内存不超过约 1.7 GiB 的已接受量级。
- **SC-007**: Radiust 接入中，推理进行期间地图与时间轴操作保持可响应；测试用户能在首次查看时 100% 正确区分观测帧与预测帧。
- **SC-008**: 省略 `zero_threshold` 时不做阈值置零；给定阈值 t 时仅值 `< t` 被置零，且置零发生在 `/255` 与 resize 前；阈值 0 不改变输入。

## Assumptions

- 首批交付目标为 macOS 原生与 Web 浏览器，两者同时纳入（2026-10-24 确认）。当前模型含 3D 卷积，浏览器 GPU 路径不可用；浏览器采用 CPU 路径，该路径已在 Apple M4 Pro 上通过数值对齐（1 线程约 7.6 秒、4 线程约 2.2 秒，非浏览器内测量）。
- 初始模型为训练中的 GhostUNet3D step 22000，仅用于部署验证；当前固定模型需要四帧、输出 tensor 为 20 帧且空间尺寸为 448×448。运行时接受任意正的同帧输入尺寸并 resize 到模型输入 tensor；固定 732×732 输入与 6 分钟步长只描述已记录训练/reference 样本，不是运行限制。
- 现有 Linux CPU 导出产物与 AZ9002 四帧样本作为数值参考；Linux 上约 4.1 秒的单次推理不作为 macOS 性能指标。
- 首批预算：单次热推理 ≤ 8 秒；内存以已实测的约 1.7 GiB 进程常驻为可接受量级。下载体积与最低设备要求尚未确定，不作为本功能验收条件。
- “本地推理”允许联网获取观测与模型文件；仅要求准备完成后的计算链路可断网。
- 公共契约的字段名、序列化格式与语言绑定在规划阶段确定；本规格只约束语义。
- 一次只服务单个模型、单个观测序列；多模型选择、批量预测不在范围内。

### Out of Scope

- 模型训练、选择与气象效果评估（由 Onix 负责；效果评估与部署正确性分别验收）。
- 数据来源发现、获取、科学解码、通用重网格与地图交互（由 Radiust 负责）。
